# Itoguruma configuration

[English](CONFIG.md) | [日本語](CONFIG.ja.md)

This guide describes the Server, CLI, Viewer, installer, and generated Codex/Claude Code settings. The server token is stored only in Windows Credential Manager; never put it in `appsettings.json`, MCP configuration, environment variables, or examples.

## Configuration Directory

| File or value | Normal location | Created or read by |
| :--- | :--- | :--- |
| Server `appsettings.json` | `<install-directory>\config\appsettings.json`; default install directory is `C:\Itoguruma` | Installer creates it from the packaged template; Server reads the directory selected by `--config-dir`. |
| Daily Server log | `<install-directory>\logs\itoguruma-server-YYYYMMDD.log` | Server; `--log-dir` selects the log directory. |
| SQLite database | Installer: `<install-directory>\data\messages.db`; direct Server default: `%LOCALAPPDATA%\Itoguruma\messages.db` | Server. The installer writes an explicit `DatabasePath`. |
| Codex MCP settings | `%USERPROFILE%\.codex\config.toml` | `itoguruma configure codex`. |
| Codex Hook settings | `%USERPROFILE%\.codex\hooks.json` | `itoguruma configure codex`. |
| Claude Code MCP settings | `%USERPROFILE%\.claude.json` | `itoguruma configure claude`. |
| Claude Code Hook settings | `%USERPROFILE%\.claude\settings.json` | `itoguruma configure claude`. |
| Bearer token | Windows Credential Manager target `Itoguruma/McpBearerToken` | Installer initializes it if missing; `itoguruma auth rotate` explicitly replaces it. |
| Viewer settings | `%LOCALAPPDATA%\Itoguruma\viewer-settings.json` | The Viewer Settings dialog stores automatic update and Windows sign-in startup preferences. |

The client setup command manages the current user's configuration and preserves unrelated entries. Restart or reload the affected AI client after configuration changes. Its full command reference is in [COMMANDS.md](COMMANDS.md).

## File Generation

The installer copies the Server's packaged `appsettings.json` template into the configured settings directory, then writes `Language`, `ServerUrl`, and `DatabasePath`. It does not put the bearer token in that file. Direct Server launches use `--config-dir <directory>` and `--log-dir <directory>`; their defaults are the Server executable directory and its `logs` child, respectively. The installed scheduled task passes both options explicitly. After installation the installer starts the Server through this task, because a Server launched directly from the Windows Installer custom action cannot see some drive paths, such as CR files under a junction to another volume, even though it runs as the same user. Only when the task start does not become healthy does the installer start the Server directly and print a warning; such a Server may not see those paths until the task starts it again at the next sign-in.

Codex and Claude Code settings are generated by `itoguruma configure codex|claude`. They contain the local proxy path, MCP endpoint, and Hook commands, but no credential value. Do not copy a profile from another machine without checking its executable paths.

## Resolution and Precedence

| Consumer | Resolution order |
| :--- | :--- |
| Server settings | `--config-dir` selects the content root; `appsettings.json` is loaded there. The standard .NET environment provider can override JSON keys using names such as `Itoguruma__ServerUrl`. |
| CLI endpoint | `--url` → `Itoguruma__ServerUrl` → `ITOGURUMA_SERVER_URL` → `appsettings.json`. The CLI first checks `ITOGURUMA_CONFIG_DIR\appsettings.json`, then the installed `config` location, its application directory, and the source-tree fallback. The first non-empty value wins. |
| CLI language | `ITOGURUMA_CONFIG_DIR\appsettings.json` when that environment variable is set and the file has `Itoguruma.Language`; otherwise English. |
| Viewer language | Same `ITOGURUMA_CONFIG_DIR` rule as the CLI; otherwise English. |
| Viewer database | `ITOGURUMA_DB` → `%LOCALAPPDATA%\Programs\Itoguruma\data\messages.db`. This variable applies to the Viewer only; it does not select the Server database or CLI business data. |

### Viewer notification area and updates

The installer starts the Viewer in the Windows notification area. Closing or minimizing its window hides it; double-click the icon to reopen it. Right-click for Settings, Check for updates, or Exit. Automatic updates and startup at Windows sign-in are enabled by default. The Settings dialog controls both options. Startup is registered for the current Windows user in `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. These preferences are stored in a per-user JSON file, separate from the Server's `appsettings.json`.

At startup, the Viewer checks the latest stable GitHub Release. If it is newer than the installed version, the Viewer downloads the matching x64 MSI and `SHA256SUMS.txt` into a temporary directory and starts Windows Installer only after the SHA-256 values match. If release lookup, download, or verification fails, the current Itoguruma remains available. Applying an update restarts the Server.

Server and CLI accept only HTTP loopback endpoints. Server `ServerUrl` must be the origin root (no path); CLI `--url` also accepts the `/mcp` endpoint and normalizes it to `/mcp`. Remote hosts, HTTPS, query strings, and fragments are not supported by these settings.

## Main Settings

### `Itoguruma` group

The group is stored in the Server's `appsettings.json`. The packaged defaults are:

| Key | Required | Type | Packaged default | Omission behavior |
| :--- | :---: | :--- | :--- | :--- |
| [`Language`](#itoguruma-language) | No | String enum | `en` | Application localization falls back to English. |
| [`ServerUrl`](#itoguruma-serverurl) | Yes for Server | Absolute HTTP URL | `http://127.0.0.1:47631` | Server startup fails; CLI must resolve its own endpoint from an option, environment, or file. |
| [`SingleInstanceWaitSeconds`](#itoguruma-singleinstancewaitseconds) | No | Integer | `5` | Server uses 5 seconds. |
| [`DatabasePath`](#itoguruma-databasepath) | No | Nullable path string | `null` | Server uses `%LOCALAPPDATA%\Itoguruma\messages.db`. |
| [`AuthenticationToken`](#itoguruma-authenticationtoken) | No | Unsupported placeholder | `null` | Ignored; authentication still requires Windows Credential Manager. |
| [`CrRoot`](#itoguruma-crroot) | No | Nullable directory path | `null` | Formal change-request delivery is unavailable. |

<a id="itoguruma-language"></a>
### `Itoguruma:Language`

- Purpose: select localized application text where the process loads the configured language.
- Type and values: string; `en` for English or `ja` for Japanese. The installer accepts only these values. Other runtime strings fall back to English.
- Default and omission: packaged value `en`; when absent, English is used.
- Source and precedence: installer `-Language` or MSI property `ITOGURUMA_LANGUAGE` writes the value to `appsettings.json`. The CLI and Viewer read it from `ITOGURUMA_CONFIG_DIR\appsettings.json` only when that variable is set. The Server's localization helper also uses `ITOGURUMA_CONFIG_DIR`; its `--config-dir` argument alone selects configuration but does not set this environment variable.
- Example: `"Language": "ja"`.

<a id="itoguruma-serverurl"></a>
### `Itoguruma:ServerUrl`

- Purpose: bind the Server and provide the default CLI endpoint.
- Type: absolute HTTP URL.
- Default and omission: packaged default `http://127.0.0.1:47631`; omission is a Server startup error. The CLI has no built-in endpoint default and fails if it cannot resolve this value.
- Constraints: Server requires a loopback origin without a path. The CLI accepts a loopback origin or `/mcp`, then sends requests to `/mcp`.
- Precedence: Server environment keys such as `Itoguruma__ServerUrl` override `appsettings.json`. For CLI, `--url` has highest priority, followed by `Itoguruma__ServerUrl`, `ITOGURUMA_SERVER_URL`, then the first configured JSON file described above.
- Installer source: `Install-Itoguruma.ps1 -ServerUrl`; default `http://127.0.0.1:47631`. The installer configures the MCP endpoint by appending `/mcp`.
- Example: `"ServerUrl": "http://127.0.0.1:47631"`.

<a id="itoguruma-singleinstancewaitseconds"></a>
### `Itoguruma:SingleInstanceWaitSeconds`

- Purpose: bound how long startup waits for another Server instance holding the same endpoint or database lock.
- Type: integer from `0` through `60` inclusive.
- Default and omission: `5` seconds.
- Invalid values: non-integers and out-of-range values stop Server startup.
- Example: `"SingleInstanceWaitSeconds": 10`.

<a id="itoguruma-databasepath"></a>
### `Itoguruma:DatabasePath`

- Purpose: select the Server's SQLite database file.
- Type: nullable string containing a file path.
- Default and omission: packaged template has `null`; a direct Server launch then uses `%LOCALAPPDATA%\Itoguruma\messages.db`. The installer writes `<install-directory>\data\messages.db`.
- Constraints: the Server process must be able to create the parent directory and write the database. This is not a CLI `--db` setting; CLI business operations use the running Server.
- Example: `"DatabasePath": "C:\\Itoguruma\\data\\messages.db"`.

<a id="itoguruma-authenticationtoken"></a>
### `Itoguruma:AuthenticationToken`

- Purpose: retained as a null placeholder in the packaged JSON template; it is not an active configuration input.
- Type and default: `null`. A string value is not read by the current Server or credential store.
- Omission: no effect on token lookup. The Server and proxy require the Windows Credential Manager target `Itoguruma/McpBearerToken`.
- Security: do not set this key or put tokens in JSON, environment variables, logs, or client settings. Use the installer to initialize a missing token or `itoguruma auth rotate` for an explicit rotation.
- Example: leave it as `"AuthenticationToken": null` or omit it.

<a id="itoguruma-crroot"></a>
### `Itoguruma:CrRoot`

- Purpose: choose the shared root used to validate formal change-request files.
- Type: nullable directory path.
- Default and omission: `null`; change-request delivery is disabled.
- Constraints: each requested file must exist below `inbox/<target_project>/` under this root and pass the canonical change-request validation rules.
- Environment override: use the standard .NET key `Itoguruma__CrRoot`. The legacy-looking `ITOGURUMA_CR_ROOT` name is not read by the current runtime.
- Example: `"CrRoot": "F:\\Workspace\\Projects\\CRs"` (replace with the shared root available to the Server process).

## Logging Settings

### `Logging:LogLevel` group

This group controls the minimum framework log severity. The Server writes its console output to the selected daily log file.

| Key | Type | Packaged default | When omitted |
| :--- | :--- | :--- | :--- |
| [`Default`](#loggingleveldefault) | Log-level string | `Information` | Framework defaults apply. |
| [`Microsoft.AspNetCore`](#logginglevelmicrosoftaspnetcore) | Log-level string | `Warning` | Inherits `Default`. |

<a id="loggingleveldefault"></a>
### `Logging:LogLevel:Default`

- Type: one of `Trace`, `Debug`, `Information`, `Warning`, `Error`, `Critical`, or `None` (case-insensitive).
- Default and omission: packaged value `Information`; without it, framework defaults apply.
- Example: `"Default": "Information"`.

<a id="logginglevelmicrosoftaspnetcore"></a>
### `Logging:LogLevel:Microsoft.AspNetCore`

- Type: one of `Trace`, `Debug`, `Information`, `Warning`, `Error`, `Critical`, or `None` (case-insensitive).
- Default and omission: packaged value `Warning`; without it, this category inherits `Default`.
- Example: `"Microsoft.AspNetCore": "Warning"`.

## Installer Settings

`Install-Itoguruma.ps1` supports these installation inputs. They affect installation or generated files; they are not persistent Server environment variables.

| Parameter | Type | Default | Constraint or omission behavior |
| :--- | :--- | :--- | :--- |
| `-Version` | String | `latest` | Uses the latest release, or the requested version/tag when supplied. |
| `-PackagePath` | File path | Empty | Empty downloads a release package; a supplied path uses that local package. |
| [`-InstallDirectory`](#-installdirectory) | Directory path | `C:\Itoguruma` | Destination root. |
| [`-PreviousInstallDirectory`](#-installdirectory) | Directory path | Empty | Empty means the same as `-InstallDirectory`; a different value migrates the existing installation from there. |
| [`-ConfigDirectory`](#-configdirectory) | Directory path | `<InstallDirectory>\config` | Server settings directory. |
| [`-LogDirectory`](#-logdirectory) | Directory path | `<InstallDirectory>\logs` | Server log directory. |
| [`-Language`](#-language) | String enum | Empty | Empty prompts interactively; accepted values are `en` and `ja`. |
| [`-ServerUrl`](#-serverurl) | Absolute HTTP URL | `http://127.0.0.1:47631` | Must satisfy the Server loopback-origin rules. |
| `-ServerStopTimeoutSeconds` | Integer | `30` | Validate range `5`–`120`; bounds the wait for the existing Server to stop. |
| `-NoPath` | Switch | Off | When present, does not add Itoguruma CLI directories to the current user's `PATH`. |
| [`-SkipCodex`](#-skipcodex) | Switch | Off | When present, leaves Codex user settings unchanged. |
| [`-SkipClaude`](#-skipclaude) | Switch | Off | When present, leaves Claude Code user settings unchanged. |

<a id="-installdirectory"></a>
### `-InstallDirectory`

- Type: directory path; default `C:\Itoguruma`.
- Omission: uses the default root. The installer stores binaries, `data`, `config`, and `logs` below this root unless those directories are overridden.
- Example: `-InstallDirectory 'D:\\Apps\\Itoguruma'`.
- MSI: set the `ITOGURUMA_INSTALL_DIR` property, for example `msiexec /i .\Itoguruma-x.x.x-win-x64.msi ITOGURUMA_INSTALL_DIR=E:\Itoguruma`. When omitted, the MSI uses the previously recorded root (`InstallDirectory` under `HKCU\Software\sazysoft\ItogurumaInstaller`), or `C:\Itoguruma` when none is recorded. The chosen root is recorded there and reused by later upgrades, including Viewer automatic updates, and by uninstallation.
- Relocation: choosing a root different from the previous one stops the Server and the tray Viewer, copies `data`, `config`, and `logs` to the new root, and rewrites `DatabasePath` when it points inside the previous root. It moves user `PATH` entries under the previous `bin`, the scheduled task, the Viewer startup entry when enabled, and the Codex and Claude Code settings to the new root, then removes the previous binaries and documents after the new Server passes its health check. The previous `data`, `config`, and `logs` are kept as a fallback copy. The two roots must not be nested.

<a id="-configdirectory"></a>
### `-ConfigDirectory`

- Type: directory path; default `<InstallDirectory>\config`.
- Omission: installer creates the default directory and writes `appsettings.json` there; the scheduled Server task receives it as `--config-dir`.
- Example: `-ConfigDirectory 'D:\\AppData\\Itoguruma\\config'`.

<a id="-logdirectory"></a>
### `-LogDirectory`

- Type: directory path; default `<InstallDirectory>\logs`.
- Omission: installer creates the default directory and passes it to Server as `--log-dir`.
- Example: `-LogDirectory 'D:\\AppData\\Itoguruma\\logs'`.

<a id="-language"></a>
### `-Language`

- Type: `en` or `ja`; default empty string.
- Omission: prompts for a language. In the MSI UI, `ITOGURUMA_LANGUAGE` is a public MSI property defaulting to `en` and is forwarded to this parameter.
- Example: `-Language ja` or `msiexec /i Itoguruma.msi ITOGURUMA_LANGUAGE=ja`.

<a id="-serverurl"></a>
### `-ServerUrl`

- Type: absolute HTTP URL; default `http://127.0.0.1:47631`.
- Omission: configures the default loopback Server origin. The installer uses the same origin for Health checks and appends `/mcp` for client settings.
- Constraints: the Server accepts only a loopback HTTP origin without a path.
- Example: `-ServerUrl 'http://localhost:47631'`.

<a id="-skipcodex"></a>
### `-SkipCodex`

- Type: switch; default off.
- Omission: when Codex is detected, installer runs `itoguruma configure codex`; when present, it does not configure Codex.
- Example: `-SkipCodex`.

<a id="-skipclaude"></a>
### `-SkipClaude`

- Type: switch; default off.
- Omission: when Claude Code is detected, installer runs `itoguruma configure claude`; when present, it does not configure Claude Code.
- Example: `-SkipClaude`.

## Client Settings

These files are generated at user scope. The generated server name is `itoguruma`; `command` is the installed proxy executable and `args` supplies the MCP endpoint. The proxy retrieves its credential from Windows Credential Manager. Do not add an `env` token entry.

### Codex MCP settings

File: `%USERPROFILE%\.codex\config.toml`.

| Key | Type | Generated value and omission behavior |
| :--- | :--- | :--- |
| `mcp_servers.itoguruma.command` | String | Absolute path to `Itoguruma.McpProxy.exe`; the server entry is unusable if missing. |
| `mcp_servers.itoguruma.args` | String array | `--url` and the absolute loopback `/mcp` endpoint; generated as a two-element array. |

Example (replace the executable path with the installed path):

```toml
[mcp_servers.itoguruma]
command = "C:\\Itoguruma\\bin\\mcp-proxy\\Itoguruma.McpProxy.exe"
args = ["--url", "http://127.0.0.1:47631/mcp"]
```

### Codex Hook settings

File: `%USERPROFILE%\.codex\hooks.json`. The generated event keys are `SessionStart`, `UserPromptSubmit`, and `Stop`; each value is an array of Hook groups with a `hooks` handler array.

| Handler key | Type | Generated value and omission behavior |
| :--- | :--- | :--- |
| `type` | String enum | `command`; required to identify a command handler. |
| `command` | String | Quoted path to `itoguruma.exe` followed by `hook --project-inbox --consumer-agent codex`. |
| `commandWindows` | String | Windows PowerShell invocation of the same Hook with the same selector and consumer. |
| `timeout` | Integer seconds | `15`; handler execution deadline. |

Example (one event; configure generates all three and preserves other handlers):

```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "<installed-cli-path> hook --project-inbox --consumer-agent codex",
            "commandWindows": "powershell.exe -NoProfile -ExecutionPolicy Bypass -Command \"& '<installed-cli-path>' hook --project-inbox --consumer-agent codex\"",
            "timeout": 15
          }
        ]
      }
    ]
  }
}
```

### Claude Code MCP settings

File: `%USERPROFILE%\.claude.json`.

| Key | Type | Generated value and omission behavior |
| :--- | :--- | :--- |
| `mcpServers.itoguruma.type` | String enum | `stdio`; required by the generated server entry. |
| `mcpServers.itoguruma.command` | String | Absolute path to `Itoguruma.McpProxy.exe`; the server entry is unusable if missing. |
| `mcpServers.itoguruma.args` | String array | `--url` and the absolute loopback `/mcp` endpoint; generated as a two-element array. |

Example (replace the executable path with the installed path):

```json
{
  "mcpServers": {
    "itoguruma": {
      "type": "stdio",
      "command": "C:\\Itoguruma\\bin\\mcp-proxy\\Itoguruma.McpProxy.exe",
      "args": ["--url", "http://127.0.0.1:47631/mcp"]
    }
  }
}
```

### Claude Code Hook settings

File: `%USERPROFILE%\.claude\settings.json`. The generated event is `UserPromptSubmit`; its value is an array of Hook groups with a `hooks` handler array.

| Handler key | Type | Generated value and omission behavior |
| :--- | :--- | :--- |
| `type` | String enum | `command`; required to identify a command handler. |
| `command` | String | Quoted path to `itoguruma.exe` followed by `hook --project-inbox --consumer-agent claude-code`. |
| `commandWindows` | String | Windows PowerShell invocation of the same Hook with the same selector and consumer. |
| `timeout` | Integer seconds | `15`; handler execution deadline. |

### `itoguruma configure` generated fields

`itoguruma configure codex|claude` is the preferred writer. It uses the current user's configuration files, updates only the `itoguruma` MCP entry and Itoguruma-owned Hook handlers, and preserves unrelated servers and handlers. Repeating the command does not add duplicate Itoguruma handlers. `unconfigure` removes only the Itoguruma entries. The installer invokes these commands unless the corresponding `-SkipCodex` or `-SkipClaude` switch is present.

## Unsupported Legacy Environment Names

The following names appeared in older instructions or are cleared during installation, but the current runtime does not read them as configuration inputs. Use the supported settings documented above instead.

| Name | Current behavior | Supported replacement |
| :--- | :--- | :--- |
| `ITOGURUMA_AUTH_TOKEN` | Not read; installer removes the current user's value. | Windows Credential Manager and `itoguruma auth status|rotate`. |
| `ITOGURUMA_URL` | Not read by Server, CLI, or proxy. | `Itoguruma:ServerUrl`, `Itoguruma__ServerUrl`, `ITOGURUMA_SERVER_URL`, or CLI `--url`, as applicable. |
| `ITOGURUMA_LOG_DIR` | Not read; installer removes the current user's value. | Installer `-LogDirectory` or Server `--log-dir`. |
| `ITOGURUMA_CR_ROOT` | Not mapped to the current configuration key. | `Itoguruma:CrRoot` in `appsettings.json` or `Itoguruma__CrRoot`. |
| `ITOGURUMA_SINGLE_INSTANCE_WAIT_SECONDS` | Not mapped to the current configuration key. | `Itoguruma:SingleInstanceWaitSeconds` or `Itoguruma__SingleInstanceWaitSeconds`. |

`ITOGURUMA_CONFIG_DIR` and `ITOGURUMA_DB` are active for the CLI/Viewer configuration resolution and language loading, and Server language loading, described in [Resolution and Precedence](#resolution-and-precedence). The installer clears their inherited user-level values before starting the Server.

## Samples

Minimal Server configuration (the token remains in Windows Credential Manager):

```json
{
  "Itoguruma": {
    "Language": "en",
    "ServerUrl": "http://127.0.0.1:47631",
    "SingleInstanceWaitSeconds": 5,
    "DatabasePath": "C:\\Itoguruma\\data\\messages.db",
    "AuthenticationToken": null,
    "CrRoot": null
  },
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  }
}
```

Install with a separate configuration and log directory:

```powershell
.\Install-Itoguruma.ps1 -InstallDirectory 'C:\Itoguruma' -ConfigDirectory 'D:\Itoguruma\config' -LogDirectory 'D:\Itoguruma\logs' -Language en
```
